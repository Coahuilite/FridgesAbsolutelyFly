# 科研、叙事与视觉家族

状态：现行行为合同。
维护责任：科研／内容维护者；视觉家族由美术维护者维护。
适用条件：本扩展科研、材料、家具文案和自生成视觉；前置规则与已接受作品按对应要求保留。

## Purpose

规定冷柜研发如何从家用低温家具逐步揭示单人太空梭，并让每个科研都有可感知的升级。材料、家具文案和图像保持涅瓦莲风格，后期能力不会提前泄露或收紧原有基础用途。

## Requirements

### Requirement: RSH-01 并行家具与逐组改装
TOFU与冷柜科研 SHALL 以涅瓦莲低温合成Nivarian_CryoSynthesis为实际前置、分别研发；TOFU可独立为全部前置认可冰箱解锁悬浮／旋转，不要求研究冷柜。睡垫按RSH-05直接开放，不再要求便携寝具科研。进入CHIVE与WALNUT及后续柜体改装须同时完成TOFU和冷柜研究，后组在全部前组完成后显现，沿CHIVE+WALNUT → ONION → BASIL+CREAM → GARLIC+PEPPER → HOPS+自主补给科研 → SALT推进；SALT仍为最终项。FAF_SPICE_DILL承担自主补给，显示名本身不另建完成状态；其他项目完成状态不撤销。自有与前置身份按CMP-02分别维护。

#### Scenario: 冷柜研究与直接开放睡垫
- **WHEN** 冷柜研究尚未完成，但玩家已有睡垫所需原材料
- **THEN** 睡垫按RSH-05直接建造，冷柜新建仍需冷柜研究；已有冷柜安装不要求另一项寝具研究，前置无垫睡眠不因本次调整被禁用。

#### Scenario: 只研究TOFU
- **GIVEN** 已完成低温合成，尚未研究本模组冷柜
- **WHEN** 完成TOFU并选择前置认可的其他冰箱
- **THEN** 可使用悬浮与旋转；后续柜体改装仍须同时完成冷柜研究，不能因独立TOFU绕过。

#### Scenario: HOPS与自主补给并列
- **WHEN** 完成共同前组并分别研究HOPS或自主补给
- **THEN** 两项各自开放近场转运或自动供液，彼此不要求对方；只有二者完成才显现并允许新研发SALT，SALT后没有新增尾项。

#### Scenario: 旧SALT已完成
- **WHEN** 载入已完成SALT但未完成原DILL节点的旧存档
- **THEN** 保留原有人类驾驶世界运输与已完成配置，不撤销SALT或重复发现信；自动供液需自主补给科研，无人世界能力还须SALT。

### Requirement: RSH-02 可见升级与真实材料
每项科研 SHALL 提供对应的真实升级；扩容或增加耐久不免费修复、补电或补液。工质改良仍使用同一种冷却液，不增加混合燃料或单位效率折扣。

#### Scenario: 完成各项研究
- **WHEN** 依次完成下表中的项目
- **THEN** 取得对应升级，不以只改变描述或新按钮代替功能。

| 科研 | 升级 |
|---|---|
| TOFU | 全部前置认可冰箱的悬浮／旋转；本模组冷柜有效柜壳重量45→5kg，内容物不减重 |
| CHIVE | 被动换热系数减半，不把主动耗电减半 |
| WALNUT | 最大耐久260→390，不免费修复 |
| ONION | 主储存12→24叠，保留真实质量 |
| BASIL | 同仓冷却液5→8份，不免费填仓 |
| CREAM | 双向温控、40°C目标上限和供电气氛 |
| GARLIC | 电池360→720瓦日、自放电5→4瓦、仅减起伏的稳定悬浮和精细角速 |
| PEPPER | 喷口外观及可选快速稳温；实际热输出与热控消耗均×3 |
| HOPS | 地图内近场转运 |
| 自主补给（原DILL节点） | 按统一目标优先使用本柜真实库存，储备耗尽才人工外部搬运兜底；不新增液仓 |
| SALT | 单人太空梭最终外观与世界发射，整合自主货运及单动物运输；轨道为可选Odyssey能力 |

#### Scenario: 上限升级不免费填充
- **WHEN** 完成容量／耐久升级
- **THEN** 上限提高但保留当前实际量；既有损伤仍需修复，仓内仍需真实电量或冷却液。

#### Scenario: TOFU只减柜壳重量
- **WHEN** 完成TOFU后携带本模组空柜或带货柜，或载入已经完成TOFU的存档
- **THEN** 有效柜壳重量为5kg，未完成时仍为45kg；每件实际货物、睡垫及舱内乘员按原质量计入携带重量，不将整柜总质量除以9，不要求打包前开启悬浮。此减重不改变其他模组冰箱的质量，也不改变净载荷上限。

### Requirement: RSH-03 家电叙事与同源视觉
从TOFU到SALT的代号科研标题 SHALL 使用Project加点分缩写，如Project T.O.F.U、Project D.I.L.L，不并列全名、中文名或效果。冷柜基础研究保留家具式命名，睡垫按RSH-05直接开放而无解锁项目。介绍首句给完整英文展开，中文翻译首句另给中文全名，英文不夹中文；随后用涅瓦莲家用科研的假正经引子和明确效果，在SALT揭示单人梭及无人／单动物运输。自主补给只说明供液，不重复导航／着陆或预告动物驾驶；睡垫独立介绍只以规整尺寸暗示联动。柜图同母图派生，长边铰接顶盖、短端设备／把手，PEPPER与SALT分别变外观。扩展简称F.A.F.，N.S.I.F.仅指前置；正式英文名`N.S.I.F Extend : These fridges are absolutely can FLY !!`，中文名`涅瓦莲睡冰箱扩展：冰箱！当然！会飞！`。



#### Scenario: 研究前后查看家具
- **WHEN** 查看前期介绍、完成PEPPER及SALT
- **THEN** 前期不提前宣告太空梭，喷口与最终梭体分两次出现；透明窗内仍显示真实人货，已接受睡垫设计保留。

#### Scenario: 封面与小图标
- **WHEN** 查看英文／中文封面、模组图标和悬浮／睡垫／世界发射动作图标
- **THEN** 封面采用已接受的涅瓦莲配色构成主义色块作品，1280×720且小于1MB，英文保留正式全名、中文版采用“睡冰箱扩展”；64×64模组图标只保留清楚的单柜，新增动作图标以图像生成并引用同源柜图，不直接使用外部Nira原立绘。

#### Scenario: 查看自主补给研究及最终发现信
- **WHEN** 在SALT前查看自主补给研究，随后完成SALT
- **THEN** 前者明确自动供液的直接收益，不预告动物／太空梭；最终信说明无人货运、动物也可作为唯一活乘员、单柜活席位与载重限制，以及床位仍仅供涅瓦莲。

#### Scenario: 科研标题与双语介绍首句
- **WHEN** 查看TOFU、DILL或其他有既定代号的科研，并切换英文与中文翻译
- **THEN** 标题保持Project加点分缩写，不把技术全名或中文名塞入标题；英文介绍首句给完整英文展开，中文首句另给对应中文名称，后续再进入引子和效果说明。

#### Scenario: 基础家具研究不改为Project
- **WHEN** 查看冷柜基础研究及直接开放的睡垫家具
- **THEN** 冷柜研究仍名“小型低温柜组装”，保留英文家具式名称，不套Project标题；睡垫没有单独解锁科研。基础柜仍名“涅瓦莲家用冷柜”／Nivarian household freezer，不把悬浮写成初始身份。

### Requirement: RSH-05 基础家具与科研入口的可发现性
便携睡垫 SHALL 无需科研即可供玩家按原材料／品质规则建造，已有冷柜也不要求寝具科研才能安装；其他安装资格、睡垫排他与柜内涅瓦莲床资格保持。首发不保留旧寝具科研Def、费用、翻译或专用兼容接缝，不迁入其他研究分支。冷柜与TOFU在可用上行页上提前可见，但实际前置和耗材仍生效；后续组按RSH-01显现，不全局放开隐藏科技。

#### Scenario: 新游戏直接使用睡垫
- **WHEN** 尚未完成本模组或自建筑构造体科研的玩家具备原材料并选择便携睡垫
- **THEN** 可以按原规则制作／建造，已有冷柜可以进行原合法安装流程，不免费生成材料或品质；不会出现需要先研究寝具或母舰轨道定位的额外门槛。

#### Scenario: 可见引入科研与后续路线
- **WHEN** 未完成实际前置时打开可用上行页
- **THEN** 冷柜和TOFU可被发现但不能免费研究，后续组保持门槛；睡垫没有额外解锁节点，也没有自组装／轨道前置。旧寝具科研完成引用不属于首发支持条件，不为内测数据增加迁移或完成率补丁。

### Requirement: RSH-06 生成资产来源与提示词可追溯
生成资产 SHALL 有可追溯的伴随元数据，区分无参考生成、带参考生成、图像编辑、程序派生及复制，并记录父源、参考用途、处理步骤和可确认的模型依据。提示词可从实际记录恢复时保留脱敏内容并标明状态；缺失或重构内容不得冒充实际调用。程序输出沿父源追溯，不伪造新的生成提示词。公开目录覆盖选定源图与全部运行图；未选入历史稿的元数据只留本地。外部参考只记录安全来源与权利依据，不改写、复制或重新授权原文件，未经核实的权利人或授权不得编造。

#### Scenario: 生成源与程序导出
- **WHEN** 将生成或编辑源图导出为游戏贴图或直接复制为封面别名
- **THEN** 目录区分生成方式与软件处理，导出图沿真实父源追溯提示词，不把裁切、缩放或复制伪称新的AI生成调用；运行PNG不因目录记录而嵌入提示词。

#### Scenario: 未知记录与外部参考
- **WHEN** 原始提示词、特定原图权利人或书面许可无法从现有记录确认
- **THEN** 明确标记相应未知或依据等级，不伪造提示词或授权；维护者转述只按转述记录，外部原图不因公开元数据而被复制或重新许可。
